# Требования к выпускной квалификационной работе (ВКР)
## Интерактивный самоучитель по языку программирования C#

---

## 1. ОБЩИЕ СВЕДЕНИЯ О ПРОЕКТЕ

### 1.1 Название проекта
**Интерактивный самоучитель по языку программирования C#**

### 1.2 Назначение
Разработка настольного приложения для обучения программированию на языке C#, обеспечивающего:
- Изучение теоретических основ языка
- Самопроверку знаний через интерактивные тесты
- Практическое применение полученных навыков через выполнение задач кодирования
- Автоматическую проверку корректности решений

### 1.3 Целевая аудитория
- Студенты, начинающие изучение C# и объектно-ориентированного программирования
- Лица, переходящие с других языков программирования
- Слушатели курсов по C# с уровнем от начинающего до среднего

### 1.4 Область применения
Образовательное учреждение, корпоративное обучение, самостоятельное обучение

### 1.5 Тип приложения
Настольное (Desktop) приложение для операционной системы Windows

### 1.6 Технологический стек
- **Язык**: C# (версия 11 и выше)
- **Платформа**: .NET 8.0
- **GUI-фреймворк**: WPF (Windows Presentation Foundation)
- **Компилятор в приложении**: Roslyn (Microsoft.CodeAnalysis.CSharp)
- **Сериализация**: JSON (Newtonsoft.Json)
- **Операционная система**: Windows 10 и выше

## 2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 2.1 Основные функции приложения

#### 2.1.1 Управление содержимым курса
**FR-1.1**: Приложение должно загружать и отображать структурированный курс из внешних источников
- ✓ Структура по главам (не менее 2 глав)
- ✓ По 21 разделу в каждой главе (структурировано)
- ✓ Иерархическое отображение в боковом меню

**FR-1.2**: Приложение должно отображать теоретический материал для каждого раздела
- ✓ Форматированный текст с поддержкой markdown
- ✓ Выделение синтаксиса кода (code highlighting)
- ✓ Примеры кода на C#
- ✓ Прокрутка и навигация по контенту

#### 2.1.2 Система тестирования (Quiz задания)
**FR-2.1**: Приложение должно предоставлять вопросы для самопроверки
- ✓ Минимум 42 уникальных вопроса (по 2 на раздел)
- ✓ Вопросы релевантны содержанию раздела
- ✓ Вопросы содержат примеры из реальной разработки

**FR-2.2**: Система должна поддерживать несколько типов вопросов
- ✓ Выбор одного правильного ответа (Multiple Choice)
- ✓ Выбор нескольких правильных ответов (Multiple Select)
- ✓ Ввод текстового ответа (Text Input)
- ✓ Верно/Неверно (True/False)

**FR-2.3**: Приложение должно обеспечивать интерактивное прохождение тестов
- ✓ Отображение одного вопроса за раз или несколько на странице
- ✓ Мгновенная проверка ответов
- ✓ Показ правильного ответа после выбора
- ✓ Сохранение результатов теста

#### 2.1.3 Система практических заданий (Code Tasks)
**FR-3.1**: Приложение должно предоставлять практические задания на кодирование
- ✓ Минимум 10 заданий на написание кода
- ✓ Постепенное усложнение задач (от простых к сложным)
- ✓ Задания охватывают ключевые концепции С#
- ✓ Каждое задание содержит описание, примеры использования и ограничения

**FR-3.2**: Структура практического задания должна включать:
- ✓ **Описание задачи** (Prompt) - четкое объяснение задачи
- ✓ **Стартовый код** (Starter Code) - заготовка для решения
- ✓ **Точка входа** (Entry Point) - класс и метод для выполнения
- ✓ **Ограничения** - лимиты времени выполнения (5 сек) и памяти (128 МБ)
- ✓ **Тестовые случаи** - набор видимых и скрытых тестов

**FR-3.3**: Приложение должно предоставлять интерфейс редактирования кода
- ✓ Встроенный редактор кода с выделением синтаксиса
- ✓ Возможность сброса кода на стартовый вариант
- ✓ Кнопка отправки решения для проверки
- ✓ Возможность копирования и вставки кода

#### 2.1.4 Встроенный компилятор и система проверки
**FR-4.1**: Приложение должно содержать встроенный компилятор на базе Roslyn
- ✓ Компиляция кода пользователя без выхода из приложения
- ✓ Обработка ошибок компиляции с указанием строки и типа ошибки
- ✓ Безопасное выполнение скомпилированного кода (sandbox)

**FR-4.2**: Система проверки должна автоматически тестировать решения
- ✓ Выполнение видимых тестов (результаты видны пользователю)
- ✓ Выполнение скрытых тестов (результаты видны только при отправке)
- ✓ Сравнение выхода программы с ожидаемым результатом
- ✓ Минимум 16 тестов (11 видимых, 5 скрытых)

**FR-4.3**: Приложение должно сообщать о результатах проверки
- ✓ Статус: Пройдено / Не пройдено / Ошибка компиляции
- ✓ Количество пройденных тестов
- ✓ Ошибки выполнения (если есть)
- ✓ Время выполнения и использованная память

#### 2.1.5 Отслеживание прогресса
**FR-5.1**: Приложение должно сохранять и отображать прогресс студента
- ✓ Сохранение выполненных заданий
- ✓ Сохранение попыток решений
- ✓ Отслеживание пройденных тестов
- ✓ Статистика по главам и разделам

**FR-5.2**: Приложение должно предоставлять статистику обучения
- ✓ Процент завершения курса
- ✓ Количество пройденных вопросов
- ✓ Количество выполненных заданий
- ✓ История попыток по каждому заданию

#### 2.1.6 Навигация и управление
**FR-6.1**: Приложение должно обеспечивать удобную навигацию
- ✓ Боковое меню с иерархией глав и разделов
- ✓ Переходы к предыдущему/следующему разделу
- ✓ Быстрый поиск по содержимому (опционально)
- ✓ Сохранение текущей позиции при закрытии приложения
